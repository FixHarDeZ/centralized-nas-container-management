# Flow production notes (moved verbatim from shopee-clip house-rules.md on 2026-11-12)

Flow-UI facts for 🤖 runs: the saved generation defaults, the new-clip ID check, multi-scene assembly in
Flow, the Scenes editor and the per-edit cost. clipjob now owns shot order, pacing and chaining; where a line
below says otherwise, `clipjob.py` and `flow-driver/SKILL.md` win.

- **`scripts/flow-verify-new-clip.js` automates step 6's positive-ID test.** `node <skill_dir>/scripts/flow-verify-new-clip.js <project-id> "<expected phrase>" "<forbidden phrase>"` → attaches to the project tab, navigates, reloads, clicks the sidebar `Videos` SPAN, opens the FIRST tile with the pointer sequence + `dblclick`, then prints `{ok, editId, expected, forbidden}` and exits 0 only when your phrase is present AND the previous clip's phrase is absent. It never reads tile counts as a verdict. Syntax-checked; needs CDP up (same `127.0.0.1:9222` as the browser).
- **Video generation default is SAVED in this project's Agent settings**: 9:16 · `x1` · `Omni 1.1 Flash` (Confirm-before-generating = `Never`). Verified by reading `mat-button-toggle-checked` in the drawer, then `Save`. Do not re-open the drawer just to confirm it — `/opt/data/clips/flow-state/<project-id>.json` records it; re-check only after Fix says he changed it.
- **Build recipe (recommended over gen-2-clips-and-stitch):** beat sheet per scene → generate scene 1 → `ffmpeg` extract its LAST frame → generate scene N+1 **with that frame as the starting frame (Frames-to-video)** + the same character chip + a **continuity block repeated verbatim in every scene prompt** (same wardrobe, backdrop, lighting, presenter) → assemble with ffmpeg (hard cut on the beat, ONE caption track, ONE music bed) → ffprobe the concat output (720x1280 / h264 / aac) + one sha256 before delivery. Without start-frame chaining the scenes jump on wardrobe/lighting and read as 4 separate clips — and identical chips + style card are NOT enough on their own: with plain crossfade the SET itself drifted (scene 1 = plain wall + plants + table, scene 2 = lamp + a coloured curtain) while presenter, wardrobe and caption style stayed matched, so paste scene 1's set description verbatim (wall colour, props, table) into every later scene prompt too, not just wardrobe. **The source of truth for that description is the extracted frame, not your own scene-1 wording** — `vision_analyze` the last frame BEFORE writing scene 2's prompt and lift the wall colour, table, props and presenter pose you actually see, because scene 1's generated set is whatever the model made, not what you asked for. **If you then CROP that frame (to drop a person, a caption or a prop), describe the CROPPED image in the prompt, not the original** — writing "she smiles at the camera" over an attached frame showing only the rolls makes the model invent the missing content or fight its own reference; vision-read the exact crop you upload and rewrite the CONTINUITY parenthetical to match it. **Fallback when no Frames control is rendered** (`Settings trigger` 0×0 → no panel at all, so there is no Frames-to-video path): `ffmpeg -y -v error -sseof -0.15 -i <scene1.mp4> -frames:v 1 <dir>/scene1_lastframe.jpg` → upload it to the project → attach it as the FIRST chip of scene 2 → say "start exactly on the attached frame" plus a `CONTINUITY:` line naming set / wardrobe / lighting. That chip-chained seam came back matching on presenter, wardrobe, set and lighting, where plain crossfade alone drifted. On the second chained scene the frame chip plus the character chip were enough, with no product image, because the frame already shows the product; attach the last frame FIRST and the character after it.
- **Assembly mechanics that actually ran clean:** chips are cleared on EVERY submit, so before each scene re-attach all of them (the Uploads/Characters lists keep the files — no re-upload) and read the in-box chip count back; number the scenes in the prompt (`ส่วนที่ 1 จาก 2` / `ส่วนที่ 2 จาก 2`), say **"Exactly 10 seconds"** in each, end scene 1 on a hand-off (presenter turns to camera / gestures at the screen) and put the soft CTA only in the last one. The agent's rewrite then shows `Part N of M` in the grid card — that string is the cheapest positive-ID cue while polling. No Scene Builder / stitch / timeline control is rendered anywhere in this DOM (the sidebar `Scenes` leaf only lists saved scene prompts), so assembly lands on ffmpeg whether or not you reach the Scenes editor below; a soft-join variant that avoids a hard beat cut: `ffmpeg -i A -i B -filter_complex "[0:v]fps=24,format=yuv420p[v0];[1:v]fps=24,format=yuv420p[v1];[v0][v1]xfade=transition=fade:duration=0.25:offset=9.75[v];[0:a][1:a]acrossfade=d=0.25[c:a]" -map "[v]" -map "[c:a]" -c:v libx264 -crf 18 -pix_fmt yuv420p -profile:v high -level 4.0 -colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv -c:a aac -b:a 192k -ar 48000 -ac 2 -movflags +faststart out.mp4` → 19.76 s from two 10.005 s sources (`offset` must be ≤ first duration − fade), then `scripts/verify-clip.py`.
- **Flow's own `Scenes` editor exists in this project** (sidebar leaf): it trims/arranges/exports a whole scene, but its scene export is **720p with no resolution choice** and there are reports of audio being stripped on export → prefer ffmpeg concat; if final quality matters, download each clip at **1080p upscale (free for subscribers)** and join those.
- **Never edit inside Flow:** an in-app video edit costs **40 credits per edit**. `Extend` is reported greyed out for Gemini Omni Flash clips (Veo only) — verify in the panel before planning around it. Cost is **per generation, not per request**, and one request may yield 2 videos charged twice → keep `x1`.
