# gameplay-clips — pitfalls

Every item cost a real run. Moved out of SKILL.md on 2026-11-12 (verbatim, grouped by the step they bite).
Read the group for the step you are on before running it; a gate that can be checked in code belongs in
`build_v5.py --check` or `clipjob.py`, not here.

## Footage source, speech gaps and burned-in text (steps 1–5)
- **Multi-title announcement trailers (Nintendo Direct / Switch 2 bundle reveals) are unusable as footage:** they cut to the other titles' logos and cinematics. Pick a single-title gameplay trailer for the product itself (search the publisher's channel, e.g. 'Gameplay Trailer' per game). Measured 2026-11-08 on RE:2 Z: F1Xpv60_yKQ had 0 gameplay frames in 130 s.
- **Trailer age gate (2026-11-08):** `Sign in to confirm your age` บล็อกทุก player_client ของ yt-dlp (tv_embedded/android/ios/mweb/web_creator) → ห้ามเสียเวลาไล่ client; หา trailer ทางการอีกตัว (ค้นด้วย web_search ชื่อเกม + "trailer") แล้วโหลดหลายตัวพร้อมกันเพื่อเทียบ
- **Trailer ทางการ Switch 2 หลายเรื่องเป็นการ์ด/cinematic ล้วน** (launch trailer RE2/3/4 = multi-title, RE3 Z Version trailer = cinematic + card, age-gated). ตรวจด้วย contact sheet ก่อนเลือก. ถ้าไม่มี gameplay ทางการ → ใช้ gameplay capture ของ creator แต่ **ต้องแจ้งฟิกเรื่องลิขสิทธิ์ก่อนส่ง** (ใช้จริงแล้ว และฟิกเป็นคนตัดสินว่าโพสต์ได้ไหม)
- **เลือก trailer จากวินาทีที่เป็นเกมเพลย์จริงและไม่มีเสียงพูด ไม่ใช่จากความยาวหรือป้ายชื่อ**: trailer เรื่องเล่าที่บรรยายตลอดได้ช่วงใช้งานประมาณ 21 วิ; trailer ประกาศอีกเรื่องมีช่วง speech-free ยาวแต่เป็น cinematic เกือบทั้งหมดจนเหลือเกมเพลย์แค่ ~9 วิ — ทำ ASR + contact sheet ทั้งสองไฟล์ก่อนเลือก อย่าอ่านช่วงว่างจาก ASR อย่างเดียว
- **ฉากจาก trailer ที่ไม่มีการต่อสู้** (ดูแค่ cinematic) ทำให้คลิป "ฟุตเทจ" ไม่ใช่เกมเพลย์: ตรวจ contact sheet ทุกช่วงก่อนล็อก seg; ถ้ามีช่วงต่อสู้แค่ช่วงสั้น ให้ใช้ช่วงนั้นทั้งหมด (เช่น 15–25 s) แทนการกระจายสั้นไปหลายช่วง
- **รวมวินาทีที่ใช้ได้ก่อนล็อกความยาว**: ช่วงที่ใช้ได้ต้องไม่มีเสียงพูด ไม่มีตัวหนังสือ/การ์ด/disclaimer/โลโก้ (ดู footage-sourcing §2) ถ้ารวมได้น้อยกว่า DUR (DUR = ความยาวที่ฟิกสั่ง; ฟิกไม่ได้สั่ง = ขั้นต่ำ 15 วิ แล้วเลือกความยาว 15–50 วิ เองตาม SKILL.md "Length") ให้เสนอทางเลือกกับฟิก (ความยาวที่ใช้ได้ / trailer อื่น / ฟุตเทจที่ฟิกส่ง) และรอคำตอบ ห้าม stretch ฟุตเทจหรือ freeze frame เพื่อให้ครบ DUR. **ทำการนับนี้ก่อน encode master และก่อน ASR** (footage-sourcing §2a: sheet + bottom-strip subtitle montage) — ถ้าไม่ถึง DUR ให้ clarify ทันทีด้วยตัวเลขจริงแล้วหยุดรอ ห้ามเผาเวลา encode/ASR ไปก่อน. ถ้า clarify ไม่ได้คำตอบรอบแรก ถามซ้ำได้ครั้งเดียว แล้วจบเทิร์นด้วย status สั้น (ยังไม่ส่งคลิป, ติดอะไร, ตัวเลือกที่เสนอ)
- **ASR (faster-whisper) หลอนบนเพลง/end-card** เช่น "The End" / "XBOX SOUND" ซ้ำทุก 2 วิ แล้ว build speech.vtt ที่ merge ทั้งช่วงเป็น speech → window ถูกปฏิเสธทั้งหมด. ตรวจ ASR JSON ด้วยตา/auto-subs แล้วเขียน `subs.en.vtt` มือ (speech = เฉพาะช่วงที่มีบทจริง) ก่อนรัน build
- **ASR ทั้งเรื่องบน CPU ใช้ ~50 นาทีต่อ 40 นาที**: รันเป็น background แล้ว poll
- **ตัวเลขช่วงว่างจาก ASR บอกได้แค่ว่าไม่มีเสียงพูด ไม่ได้บอกว่าไม่มีตัวหนังสือ**: กล่องบทสนทนาและแถบซับในเกมนับเป็นข้อห้ามเหมือนเสียงพูด — ก่อนพูดกับฟิกว่า "น่าจะพอ" ต้องนับวินาทีที่ผ่านทั้งเสียงและภาพแล้ว (footage-sourcing §2/§5) ไม่ใช่รวมช่องว่างของ ASR ตรงๆ
- **ช่วงเสียงอังกฤษใน trailer ที่มีบทพูดในเกม** VTT ของ auto-subs อาจไม่มีบทในเกม: ยืนยันด้วย `scripts/asr_speech_spans.py` ก่อนเชื่อ gap ทุกครั้ง
- **ASR (faster-whisper small, TH/EN) พลาดบทในเกม (2026-11-09 RE3 Switch 2 run):** window ที่ ASR บอกว่าเงียบ 432–453 s มี subtitle บทพูดจริง "What the fuck!?" ที่ 447–448 s และ "Jill! Over here!" ที่ 453. → ก่อนล็อก seg ต้องทำ bottom-strip subtitle montage (footage-sourcing §5b) ทุกช่วง แล้วตัดก่อนบทแรกที่เห็นในภาพด้วย margin ≥0.5 s ไม่ใช่เชื่อ ASR อย่างเดียว
- **Combat trailers: ASR บอกเงียบทั้งที่มีเสียงคราง/กรี๊ดของตัวละคร ("Uh ah!", "Huh.")** — auto-subs VTT จับได้แต่ whisper ไม่จับ และ ASR รอบใหม่บนไฟล์เดียวกันอาจคืนช่วง speech ต่างจากรอบก่อน → ใช้ union ของ VTT + ASR ทุกรอบ, วาง seg ให้จบก่อนเสียงแรก ≥3 วิ, ยืนยันด้วย bottom-strip ซับ. `build_v5 --check` บน speech.vtt ใหม่คือตัวตัดสิน — ถ้ามันปฏิเสธ seg ให้ย้ายช่วง ไม่ใช่แก้ VTT ให้ผ่าน.
- **Trailer ที่ไม่มีเสียงพูดแต่มีแคปชั่นเกมเกือบตลอด**: `asr_speech_spans` ได้ 0 segment ไม่ได้แปลว่าช่วงนั้นใช้ได้ — ตัวหนังสือบนภาพต้องนับแยกจากเสียงเสมอ. Contact sheet ที่ 1 fps พลาดแคปชั่นสั้น ๆ: ส่งแผ่น 0.5 วิ (`fps=2,scale=240:135,drawtext=…,tile=8x10` ด้วย `-ss` ก่อน `-i` แล้วเผาเวลา `t+offset`) เฉพาะช่วงที่สงสัยก่อนตัดสิน. ถ้าช่วงสะอาดรวมได้น้อยกว่า DUR (ที่ฟิกสั่ง หรือ 15 วิ) ให้ clarify กับ Fix พร้อมตัวเลขวินาทีที่ใช้ได้จริงและตัวเลือก (ความยาวที่ทำได้ / เลือก trailer อื่น / ยอม HUD) ห้ามลดความยาวเงียบ ๆ.
- **ซับต้นทางค้างในช่วงต้น window:** trailer บางเรื่องเผาซับจีน/อังกฤษค้างหลังเสียงบรรยายจบ 0.5–1 วิ → ตรวจ bottom strip (crop ล่าง 300px ที่เฟรมจริง ทุก 0.6 วิ) ที่จุดเริ่ม window ทุกครั้ง แล้วเลื่อน in ให้พ้น; หลังเลื่อนตรวจต่ออีกหน้าต่างที่จะใช้ (ช่วง end ก็อาจมีซับเริ่มใหม่)
- **Watermark ช่องเกมของแชนแนล (เช่น Nintendo Hall มุมขวาล่าง 1280x720 ~x1105–1280 y570–720)**: crop `crop=1100:619:0:0` ตอน encode master (ไม่ใช่ hero) และ hero ใช้ center crop ซึ่งไม่โดน
- **trailer ทางการมักมี watermark สองจุดคนละแนว: bug ผู้จัดจำหน่ายมุมบน-ขวา (ลอย ~y30–110) กับ credit line บรรทัดล่าง (~y1000–1035)** → ห้ามแก้แค่จุดเดียว: hero ของ build_v5 ครอป *แนวนอน* เท่านั้น (608×1080 กลางเฟรม) จึงทิ้ง credit ล่างไว้เสมอ ให้ครอป "แถบสะอาด" ออกจาก source ก่อน (`crop=<กว้าง>:<สูง>:<x>:<y>` เลือก y ให้พ้นทั้งสองเส้น แล้วครอป 16:9 ออกจากแถบนั้น) แล้วชี้ทั้ง `master` และ `trailer` ใน plan ไปที่ไฟล์ที่ครอปแล้ว — ชี้ `trailer` ไปที่ไฟล์ต้นฉบับ = hero มี credit ติดมา. วัดตำแหน่ง watermark ด้วย bounding box สีบนเฟรมที่พื้นดำ/สว่าง (red-vs-G/B ผ่าน ImageChops) ไม่ใช่ถาม vision
- **เลือก hero/window จาก contact sheet ก่อนเสมอ**: ฮีโร่ crop 9:16 จับกล่องบทสนทนา (ตัวหนังสือ EN ฝั่งซ้าย) ได้ง่าย → ใช้ช่วงที่กล่องว่าง/ยังไม่พิมพ์ (ดูเฟรมทีละ 0.4 วิรอบจุดตัด) ส่วน window ที่มี dialogue/ตัวหนังสือในภาพก็เลี่ยงถ้ามีทางเลือก
- **การ์ดท้าย trailer มักมีโลโก้แพลตฟอร์มอื่น (PS5/Xbox/Steam) — Shopee ห้ามโลโก้แพลตฟอร์มอื่น** → อย่ายืมการ์ดท้ายที่มีโลโก้ ใช้ช็อตเกมหรือการ์ดชื่อเกมที่ไม่มีโลโก้แทน (เจอ 2026-11-06 DQ Monsters)
- **OCR เฟรม *หลัง* การ์ดท้ายก่อนยืม**: trailer มักตัดจาก title card ไป DLC/price promo ทันที (เฟรมถัดจากการ์ดท้ายที่สะอาดมีแบนเนอร์ $29.99) → เลื่อน out ให้จบก่อน card ตัวนั้น; เลื่อนไม่ได้ = การ์ดนั้นใช้ไม่ได้ เพราะราคาห้ามอยู่ในเฟรมเดียวกับภาพที่ส่ง
- **ฟิกส่งลิสติ้งที่รูปปกกับชื่อสินค้าไม่ตรงกัน** (เช่น รูปเป็นเกมเวอร์ชันเดิม แต่ชื่อลิสติ้งเป็นภาคใหม่ pre-order) → ใช้ชื่อลิสติ้งเป็นตัวตัดสินสินค้า ใช้ปกของสินค้าจริงจาก press kit ของค่าย (ดู `ddx`/key art) แทนรูปลิสติ้ง และบอกความต่างนี้ใน delivery
- **ภาพที่ฟิกส่ง (โฆษณา Shopee) = ข้อมูลสินค้า** — ห้ามเอาส่วนที่มีราคา/โปรโมทเข้าคลิป
- **Source trailers over ~20 minutes: encode only the window you use.** A 31-minute gameplay upload is about 300 MB at 1080p. Cut the window with `-ss S -t D` at 1080p (`trailer_cut.mp4`), then build the 720x1280 master from that cut. Keep the cut as `trailer` and the master on the same timeline (t=0 = S), so no rebase is needed.
- **Printed icon, QR or price inside the cover art bbox.** Vision bounding boxes for a game cover can include a QR, a shopping-bag icon or an orange mark printed on or beside the artwork; these then show up in the sticker and the thumbnail. Cut the crop above the lowest printed element, re-crop, and vision-check the new crop before using it.
- **nintendo.com บางเรื่องมีแค่ key art 1920x1080** — ไม่มี `--ill/--strip` ก็เว้นได้ อย่าไล่หา PNG ใส

## Audio: VO, duck, loudness (steps 5, 7, 9)
- **VO สั้นกว่าเดดไลน์ (vo_end < DUR−3):** เพิ่มประโยคใหม่ + gap_after 0.30–0.40 แล้ว gen ใหม่ (เสีย 1 request) — ปรับ gap อย่างเดียวด้วย --from-take ไม่พอ ถ้าขาดเกิน ~1.5 วิ
- **บทพูดยาวเกินไป = ต่อเนื่องไม่มีช่องหายใจ** (raw take 18.8 s speech แทบไม่มี gap) → เหลือ 5 วลีสั้นต่อ 20 วิ (speech ~14 s + gap 0.5 s)
- **ฟิต VO เข้าเดดไลน์ DUR−1.5** (เดดไลน์เทียบกับ *ซับ* ไม่ใช่เสียงพูด ซับจบหลังเสียงประมาณ 0.1 วิ): ตั้งเป้าให้วลีสุดท้ายจบ ≤ DUR−1.6. ลำดับปรับ ทุกรอบรัน `--from-take` (0 request): (1) `lead` 0.05; (2) `tempo` 1.07→1.08 (เกิน 1.08 ฟังรีบ); (3) gap_after ทุกช่อง ≥0.28 — ค่า 0.25 พอดีไม่นับเป็น gap >0.25 แล้ว GATE WARN; (4) ค่อยตัดคำ. มี `--check` ที่บรรทัด `VO end` ถ้าขึ้น LATE ทั้งที่ speech end ≤ เดดไลน์ ให้ดูว่าซับจบเกินหรือไม่. **บันไดนี้กู้ได้แค่ ~1 วิ** (lead + gap + เพดาน tempo 1.08) — take แรกเกินเดดไลน์ตั้งแต่ ≥1.5 วิ = ตัดบท ~25–35% แล้ว gen take ใหม่ (1 request) ทันที อย่าหมุน `--from-take` หลายรอบ; ก่อนเขียนบทให้คิดงบอักขระไว้ก่อน: (เดดไลน์ − lead − ผลรวม gap) × 10–16 อักขระ/วิ
- **VO Gemini 3.8 หมดโควตาวันเดียวกับ demo แล้ว → สคริปต์ไล่ไป 3.1 เอง** (stdout `engine used`, vo.engine) — ไม่ต้องแก้ plan ยกเว้นฟิกต้องการเสียงรุ่นล่าสุด
- **edge-tts**: อ่านบทจากไฟล์ผ่าน `uv run --with edge-tts python script.py` เสมอ (`uv tool run edge-tts --text` กับไทยยาว = `NoAudioReceived` จาก quoting); `NoAudioReceived` สุ่มจากฝั่ง service ได้แม้พารามิเตอร์ถูก → รันซ้ำแล้ว gate ด้วยผลจริง ห้ามไล่แก้ parameter; edge ขึ้นบรรทัดใหม่ = pause ~0.95 วิ, ช่องว่าง/จุด = 0 วิ, SSML `<break>` ถูกอ่านทิ้ง → คุมจังหวะด้วยการสังเคราะห์ทีละวลีแล้วต่อ silence เอง (ที่ `gen_vo_natural.py` ทำ)
- **เสียงฟัง "เหมือน AI" (edge / fallback A)**: (1) บทภาษาพูดประโยคสั้น, (2) อารมณ์/rate/pitch ต่อวลี, (3) post-chain `highpass=f=120,equalizer=f=220:g=-7:w=1.2,equalizer=f=2400:g=5:w=1.2,equalizer=f=4500:g=-4:w=1.3,equalizer=f=7500:g=2.5:w=1.0,acompressor=threshold=0.2:ratio=2:attack=12:release=200:makeup=1` → level-match mean กลับเท่าเดิม → `alimiter=limit=0.9:level=0` (**`level=0` บังคับ** — auto-level boost กลับ). boost 180 Hz = เสียงโคลน ห้าม
- **TTS ตัวใหม่ทดสอบด้วย ASR เทียบบทจริง**: `uv run --with faster-whisper` **raw numpy path** (`ffmpeg -f f32le -ar 16000 -ac 1` → `np.frombuffer` → `transcribe(array)`) — ส่ง path ไฟล์ตรงๆ ชน `av.open() metadata_errors` บน Python 3.14; วัด duration ต่อวลีว่าสั้นผิดฟิสิกส์ไหม. `mimo-v2.5-tts` ไม่มีเสียงไทย (ทดสอบแล้ว อย่าลองซ้ำจนกว่าจะประกาศเพิ่ม voice ไทย)
- **volume ต้องจูนเป็นคู่กันและวัดซ้ำทุกครั้ง** — ค่าที่เคยผ่าน (music 0.75/0.38/0.30 กับ VO 1.25/1.35/1.40) ไม่รับประกันกับ trailer ใหม่; ปรับ `music_gain` ลงจน duck-only delta ≥6 dB โดย max ยังไม่แตะ −3 — ขั้นตอนที่ใช้ได้จริง: วัด delta ด้วยช่วง VO ทุกวลี แล้วลด `music_gain` ทีละ ~2–3 dB (0.75 → 0.5 → 0.4 → 0.33) พร้อม build + master ใหม่ทุกรอบ เพราะ master จะเพิ่ม gain กลับเอง (ต้องวัด max หลัง master เสมอ) ลดดนตรีเป็นทางเดียวที่ไม่กระทบ duck threshold
- **จูน `music_gain` ด้วย `duck_gate.py --gain <x>` ก่อน rebuild** — มันวัด delta จาก master + vo โดยไม่ต้อง render ใหม่ ลองค่า (0.75 → 0.5) จนผ่าน ≥6 dB แล้วค่อย build ครั้งเดียว.
- **Duck-only render ต้องมี `ffmpeg -y`** — ไม่มี `-y` ffmpeg ถาม `Overwrite? [y/N]` แล้วออกเงียบๆ ทิ้ง wav เก่าไว้ สคริปต์วัดจึงอ่านผลของ build รอบก่อน และตัวเลขดูปกติ. ทุกครั้งที่ build ใหม่ (แม้แค่ตัด seg) ต้อง regenerate duck-only ก่อนอ่าน delta เสมอ
- **วัด gate เสียงด้วยช่วงที่ไม่มี VO จริงๆ** — เซก CTA ดนตรีดังทำ delta ดูต่ำกว่าความจริง; VO ยาวเกือบทั้งคลิป → ใช้ duck-only render
- **Duck gate ผ่านเป็นเท็จเมื่อ footage เงียบ**: gameplay บางช่วงมีเสียงเกมแค่ ~−45 dB (the delta is relative, so a near-silent seg can show a large delta with no music to duck) → before accepting the gate, run `volumedetect` on each seg's audio range in the master. A seg under ~−35 dB: re-plan a louder window from the same gap (plan change only, no re-encode) if one exists; otherwise state in the delivery that the clip is VO-led there. Never report the gate as passing on the relative number alone.
- **Walking/fire footage มักเงียบมาก (mean −35…−40 dB ต่อ seg)**: เลือกช่วงที่ดังกว่าในช่องว่างเดียวกัน (วัด `volumedetect` ทุกช่วงก่อน build) ถ้าไม่มีให้บอกใน delivery ว่า VO-led.
- **volumedetect` ต้องรันโดยไม่มี `-v error`** (ผลอยู่ระดับ info)

## Thai subs (steps 8–9)
- **libass ต้อง `shaping=complex` (ใช้ filter `ass=` — `subtitles=` ไม่มี option นี้)**: ค่า default ของ ffmpeg build นี้ shape แบบ simple → วรรณยุกต์ซ้อนบนสระบน (ขึ้น/ที่/นี้) ทับสระจนอ่านเป็น "ขึน" (วัดด้วย bbox เทียบ render `ขึ` กับ `ขึ้`: simple สูงขึ้น ~2px, complex สูงขึ้น 24px — **อย่าเชื่อ vision เรื่อง mark ซ้อนหาย/ไม่หาย** มันตอบผิดทั้งสองทาง ใช้ bbox ตัดสิน). สคริปต์ในสกิลใส่ให้แล้ว — สคริปต์/คำสั่ง ffmpeg ใหม่ทุกตัวที่เผาซับไทยต้องใส่เอง. `sub_linecheck.py` นับเฉพาะพิกเซล fill (LIT=120) เพราะขอบน้ำตาลเชื่อมสองบรรทัดเป็นแถบเดียว
- **ซับ: ต้องเขียน `\\N` ใน plan.json (ได้ `\N` ในไฟล์)**: `gen_vo_natural.py` ใส่ข้อความ `sub` ลง ASS ตรงตัว. ถ้าเขียน `\\n` ไฟล์จะได้ `\n` ตัวเล็ก — libass ถือเป็น soft break และ sub_linecheck นับ `want=1` แล้ว FAIL ทั้งที่ตั้งใจสองบรรทัด. ตรวจก่อน build: `grep -c '\\N' subs.ass` ต้องตรงกับจำนวน event ที่ตั้งใจแบ่งบรรทัด.
- **ซับไทย: ตรวจด้วยโครงสร้าง ไม่ใช่ OCR** — เวลาแสดง/หายด้วย subprobe บนแผ่นดำ (`signalstats` YAVG: ดำ TV-range = 16 → เกณฑ์ `>17`), จำนวนบรรทัดด้วย `sub_linecheck.py`. **`bands=1` จาก event 2 บรรทัดมักเป็น false positive ด้วยกลไกนี้: mark สระบน/วรรณยุกต์ของบรรทัดล่างกับหางตัวอักษรของบรรทัดบนมีแถว lit ต่อเนื่องกันในช่วง ≤4 px ที่ group ของ linecheck รวมได้ ทั้งที่ *ตัวเนื้อบรรทัด* (fill) สองบรรทัดยังห่างกัน ~25–35 px** → ชี้ขาดด้วย `scripts/sub_bandprofile.py <dir>` (นับ fill ต่อ event: ห่าง ≥16 px = false positive → ผ่าน + จดเหตุผลใน notes; ห่าง <16 px = บรรทัดชนจริง → แก้ข้อความซับ) — deterministic ไม่ต้องพึ่ง vision; เก็บ crop zoom (`crop=720:340:...` scale 2x) ไว้เป็น fallback (แถบแคบคืน blank ได้ทั้งที่ซับขึ้นปกติ)
- **sub_linecheck FAIL จากคำละตินในบรรทัดไทย** (เช่น `ถ้าชอบ Hitman ...` ได้ `bands=2 want=1`): ตัวอักษรละตินกับวรรณยุกต์ไทยทำให้แถบแยกเป็นสองช่วงที่ x เดียวกัน — ไม่ใช่ซับยาวเกิน. ยืนยันด้วย crop ซับ 2× ของเฟรมจริงก่อนแก้ข้อความ; ถ้าอ่านครบเส้นและไม่ล้นกรอบ ให้ปล่อยผ่านแล้วบันทึกเหตุผลใน notes
- **Sub ซ้อนสองบรรทัดทำให้ linecheck FAIL แต่คลิปปกติ**: ตรวจด้วยรูปร่างซับ (จำนวน band ต่อ event) ไม่ใช่ตัวเลขรวม — ถ้า event ที่ตั้งใจให้เป็นบรรทัดเดียวออกสองแถบ ให้แบ่งด้วย `\N` ตั้งแต่บทแล้ว build ใหม่ (ไม่ต้องเร่ง/ย่อ VO).

- **Work dir ต้องมีไฟล์ครบก่อน build**: `build_v5.py` resolve path ของทุกคีย์ใน plan เทียบกับโฟลเดอร์ plan.json — ต้องมี `fonts/` (โฟลเดอร์ ไม่ใช่แค่ .ttf ที่ราก), `subs.en.vtt`, `master.mp4`, `trailer.mp4`, `bg.png`, `vo.mp3`. ขาดไฟล์ใดไฟล์หนึ่งพังที่ขั้นตรวจก่อน render (FileNotFoundError) — ตรวจว่าครบก่อนรัน `--check`.

- **Minimal build_v5 พลาดเมื่อ no-speech source**: plan ที่ผ่าน `--check` ต้องมี `vtt` เป็นไฟล์ header-only (`WEBVTT`), ไม่มี `beats`, ทุก seg `snap:false`, และ `dur` = ผลรวม seg; ปรับ `music_gain` ด้วย `duck_gate.py --gain` (ในเคสนี้ 0.75 ได้ delta 4.1 dB, 0.4 ได้ 8.2 dB) ก่อน rebuild.

## Vision checks
- **Vision: ถามเป็นแผ่น คำถามสั้น 1 บรรทัด/เฟรม**; ห้ามเชื่อชื่อเกม/โลโก้/วันที่ที่อ่านจากแผ่น (แต่งชื่อเกมขึ้นใหม่ได้) — ยืนยันด้วยเฟรมเดี่ยว + crop zoom; vision ขัดกันเอง → วัดด้วย pixel (ความสว่าง/นับพิกเซลสี) เป็นคำตอบสุดท้าย. **`vision_analyze` timeout (420 s) บนแผ่น = อย่า retry แผ่นเดิมซ้ำ** (ซ้ำแล้วก็ timeout) — **แผ่นที่ต้องตอบ 1 บรรทัด/ไทล์ ให้ ≤ ~10 ไทล์/call**: 19–36 ไทล์ timeout ซ้ำ ๆ → ประกอบซับชีตใหม่จากเฟรมเดิมด้วย PIL (ไม่ต้อง ffmpeg ใหม่) แล้วถามทีละชีต; ยัง timeout ค่อยเหลือ crop เดียวคำถามเดียว (ภาพ ~880×260) แล้วประกอบคำตอบเอง
- **Chk ชีต 2 วินาทีต่อเฟรมให้ผลต่างกันระหว่างรอบ** (callout เช่น AIR STRIKE มักถูกมองว่าเป็น C) → เลือกช่วงที่สองชีตตรงกันเท่านั้น และรัน frame check ตอนท้ายเสมอ
- **แฟลชขาวที่ seam ต้องวัดด้วย mean luminance ไม่ใช่ถาม vision**: vision ตอบ "ไม่มีแฟลช/เป็น hard cut" ทั้งที่แฟลชขึ้นจริง — ดึงเฟรมรอบ seam (`-ss` ห่าง ~0.033 วิ = 1 เฟรม) แล้ววัด mean ด้วย numpy; spike แบบ 134 → 176 → 147 ที่จุดตัด = แฟลช 0.5 alpha 3 เฟรมตาม plan (ผ่าน), ขาวเกือบ 255 ค้างหลายเฟรม = แรงเกิน → ลดค่าใน `flash` แล้ว rebuild

## Hermes terminal and tooling
- **Gate script: `python3` ของ NAS ไม่มี numpy** → ใช้ `uv run --with numpy python <file>.py`. และ **อย่าใส่ heredoc ที่อ้างอิงไฟล์ wav/mp4 ขนาดใหญ่ใน terminal** — lifecycle guard จะ block คำสั่งที่อ้างไฟล์ >1 MB ว่าเป็น script ที่สแกนไม่ได้. เขียนสคริปต์วิเคราะห์เป็นไฟล์ `.py` ด้วย write_file แล้วรันแบบ path
- **งานหลายนาที → `terminal(background=true)` + รอ/เช็คไฟล์ output** — sleep-loop ใน `execute_code` โดน timeout แล้ว kernel state หาย; `pgrep -f` match shell ที่ poll เอง. `process_manage(action=wait)` clamps each call to 180 s, so repeat waits until the process exits; a foreground call promoted past 600 s also ends up here.
- **Shell `( cmd & )` ใน terminal foreground ถูกปฏิเสธ**: ส่งงานเรนเดอร์/ASR เป็น `terminal(background=true)` แล้ว poll ไฟล์ output ในคำสั่ง foreground สั้นๆ ไม่ใช่ sleep ยาว.
- **งาน background แจ้ง complete ช้าได้** — ห้ามฟันธงว่าไฟล์ถูกแทนที่จาก notification; เทียบ sha256 กับ `delivery-log.jsonl`
- **รัน measurement ทุกช่วงใน call เดียวด้วย loop** — วัดทีละ call กิน tool-call จนถูกตัดก่อนถึงขั้นส่ง
- **สำเนาสคริปต์ที่แก้ด้วย `patch` แบบ fuzzy → grep identifier ก่อนรัน**; สคริปต์ VO เขียน `vo.mp3` ก่อน `subs.ass` → crash กลางทางทิ้ง subs เก่าไว้ → เกทด้วยบรรทัด `events: N` + `repr()` ของ Dialogue; `re.sub` แปลง `\n` ใน replacement เป็น newline จริง → ใช้ lambda/`str.replace`, backslash ประกอบด้วย `chr(92)`
- **grep URL ที่มี quote ใน terminal พัง** → ใช้ Python `re.findall`
- **Never `source` /opt/data/.env in the shell to get an API key.** A command that sources the secrets file gets held for approval, times out, and stalls the whole clip run. The VO script reads `GEMINI_API_KEY` from `/opt/data/.env` itself, so run `gen_vo_natural.py` with no env prefix. If a command is blocked for approval, stop and ask Fix once; do not rephrase it to reach the same outcome.
- **`terminal(workdir=…)` must be an existing directory.** A nonexistent workdir returns exit 126 with a stale `cd` error, the same symptom as the persisted-cwd trap. Set `workdir=/opt/data` (or any existing dir) and do the `mkdir` inside the command.
- **Gate ที่รันผ่าน pipe: `… | tail/grep; echo $?` คืน rc ของ pipe ไม่ใช่ของสคริปต์** (บางสคริปต์พิมพ์ `no subs.ass in <dir>` แล้วยัง exit 0 ผ่าน tail) → อ่านบรรทัด verdict จาก stdout เองเป็นเกณฑ์ (ต้องเห็น `SUB STRUCTURE PASS` / `DELIVERY CHECK: clean` / `PASS`) หรือ `set -o pipefail` ก่อน pipeline — ไม่มีบรรทัด verdict = ไม่ต้องอ้างว่าผ่าน
- **`pkill -f <pattern>` ที่ pattern ไปโผล่ในคำสั่งตัวเอง = ฆ่า shell ของ terminal call นั้น** (wrapper ส่งทั้งบรรทัดเป็น cmdline ของ bash) → call คืน exit −15 เงียบ ๆ ทั้งที่งานยังไม่จบ; ใช้ `[p]attern` bracket trick หรือ `pgrep` เอา PID มาก่อน kill
