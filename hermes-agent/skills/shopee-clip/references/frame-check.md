# Frame check — defect classes, and running the gate when vision reads fail

Standing depth for SKILL.md step 10 (per-shot review). Step 10 owns WHAT to sample and the delivery format; this file owns the defect classes that decide the verdict and the workflow when `vision_analyze` itself is failing.

## Defect classes
- **A price-shaped detail IS a price.** A yellow/green shop sticker on the case's shrink wrap — or any price tag the model paints onto the product — counts as a price defect even when its figures are illegible. Report it as a sticker with its frame time; never fold it into "no price reached the screen", and never quote a figure you could not read. Both directions matter: an unread price must not be claimed present, and a present price-shaped tag must not be reported away.
- **A zoom settles only the frame it zoomed.** Two frames of the SAME date caption can return different years (2026 vs 2020) while both read the same Thai day/month line — the year is the model's preferred silent swap. When zooms disagree on a digit, that date's year is UNREADABLE: give Fix both candidates plus the brief's date, and do NOT pick the candidate that matches the brief — a hallucinated digit matching the brief is indistinguishable from the real one.
- **Two reads of ONE zoomed crop disagreeing about a printed detail is a cue to change the FRAME, not the wording.** Re-asking the same crop buys a third guess — instead sample a different frame where the product is held larger and ask the identical pointed question ("is there a red band across the case's top edge, transcribe it"). Agreement between two such frames is the verdict; continued disagreement means the detail is illegible, so quote every candidate with its frame time and let Fix judge from the clip. Never clear a frame on the single read that happened to agree with the brief.
- **A printed GAME TITLE that full-frame reads report as a different instalment is an OCR guess, not a wrong-game defect.** Stylised cover lettering makes full-frame reads substitute the franchise's better-known entry (plus an invented subtitle) on the very frames where a zoom of the title region reads the product's own title. So zoom the title region before reporting cover-title fidelity in EITHER direction; when zooms of the title disagree across frames, the title is illegible — quote every candidate with its frame time and never present the more famous title as what is on screen.
- **A printed STICKER whose text returns a NEW Thai string on every read is ILLEGIBLE — including shop-name-shaped strings.** Language-support notices and distributor seals read back as a different (sometimes store-shaped) name per read; the no-shop-name rule is violated only when two reads agree on a name. Report the candidates with frame times for Fix to judge from the clip: never fold an unread sticker into "no shop name reached the screen", and never assert the violation off one read either.
- **An on-screen SPEC the brief never stated is a factual defect of the same weight as a wrong date.** The model invents ratings and numbers that look native (`IPX6 Water` from a brief that only said กันน้ำ, a capacity, a size, a count), and the invented figure reaches the buyer as a claim. Compare every caption's claimed spec against the brief word by word, not just its digits: report it with its frame time as "ไม่ได้ระบุใน brief", and in the fix swap it for the brief's own wording (`Water Proof`) rather than deleting the beat. The other direction binds too — do not strip a spec that IS in the brief just because it looks like a number.
- **The PRODUCT itself can drift between shots while presenter, set and captions stay matched** — a transparent shell turns opaque, a printed LED strip, port or window disappears at one beat, because every shot is re-drawn from the reference rather than re-used. So ask each sampled frame the same property question the brief makes load-bearing (shell type, visible display/LED, ports, colourway, cover art) and, when the answer changes across frames, report the exact frame time and which property changed. Prevention belongs in the prompt, not only the check: a `PRODUCT LOCK` line naming the properties that must be visible in EVERY shot, repeated verbatim in each scene, is what keeps a key selling point from vanishing mid-clip.
- **A product drawn at the wrong real-world scale fails the clip even when every shape question passes.** A kids' drawer unit rendered wardrobe-tall answers the drawer-count questions correctly and still fails Fix's review (size เลือกเกินจริงไปมาก). Prevention is prompt-side: real dimensions PLUS a body anchor (`its roof reaches only her HIP when she stands beside it`) — the no-size rule bans cm from VO/on-screen, not from the prompt. Verify per frame by asking where the product's top lands on the presenter (knees / hip / chest) against the reference photo's proportions, and report the frame time when it moves.
- **A full-frame read that reports a shop watermark or platform logo needs a ZOOM of that exact corner before it enters the delivery in EITHER direction.** A caption-height decorative graphic (a sparkle, star or sticker beside the caption) reads as a Shopee-style shopping-bag logo at full-frame scale, while a small real corner badge can vanish inside a prose description — so crop that corner (`ffmpeg -vf crop=W:H:X:Y,scale=2*`) and re-read it: only what survives the zoom is reportable, exactly as for price and date claims. A watermark verdict off one full-frame read is never a verdict — not to assert the violation, and not to clear the frame either.
- **Report which prompt-requested captions actually rendered.** The agent rewrite picks its own caption set and can silently drop a caption you asked for (a date caption like `Restock 24 Nov` never appearing while the other beats caption fine): absence is not a content defect, but the delivery names it — Fix needs to know the on-screen info carries less than the prompt asked, and a dropped date is exactly the claim a buyer looks for.
- **Garbled engraving on the product is not an on-screen-text defect when the real product carries engraving there.** Vision flags a lid's embossed brand mark (`KATHY AMREZ` re-drawn as `KATHYAMREZ`/`AVYA`) as "pseudo-text" because it applies the ON-SCREEN TEXT: NONE clause to the object itself. Check the source photo: if the real product has a mark in that spot, the re-drawn mark is product fidelity. At most, name it as "engraving reads soft" in the review. Only captions, overlays and invented labels count as text defects.
- **Presenter identity is a frame-check question on every P/R shot. Ask it about shot 1 BEFORE the review send (Fix caught it 2026-11-09: น้องเนย was attached, but the presenter rendered as น้องมิ้นท์ from shot 1 onward).** The chip alt only reads `Character ingredient image`, so it cannot prove which character is attached. Put the chip image and the rendered frame side by side in ONE vision call and ask whether they show the same person (hair, face, outfit). **Getting the chip when nothing local has it:** over CDP on the open Flow project, click the `Characters` button, then walk each name `SPAN` up to ~5 ancestors for its `img.src` — each tile URL carries its OWN `Signature`, so copying one tile's query string onto another returns a 337-byte error body; download every full URL, lay the N cards out as a numbered PIL grid beside the rendered face, and ask which NUMBER matches. **A grid pick alone is not a verdict:** confirm with a second two-panel VIDEO-vs-chosen-card read; when the two disagree, identity is UNSETTLED — report it as unsettled with both candidates, never as a settled mismatch. A CHARACTER chip's `img.src` serves an HTML page instead of an image to a cookie-less fetch, so when the fetched bytes are HTML, crop the chip rect out of a prompt-box screenshot (PIL, 5–6x LANCZOS) and use that zoom. A mismatch is a defect: report it in the review message with the re-gen cost. In manual mode, name the character Fix must attach, and run the same comparison on his render.
- **Ask each shot whether its planned ACTION happened, prop state included.** A presenter result shot can pass on look and voiceover while the compact stays closed and the eye and lip touches never happen, so the voiceover (`แก้ม ตา และปาก`) claims what the frames do not show. Put the planned action in the vision question verbatim, including open/closed state and each touch point. A miss is a defect for the review message, offered as a choice between keeping it (0 credits) and re-generating it (with the cost).
- **Thai captions read at thumbnail scale are not evidence of their wording.** Contact sheets and downscaled frames make the model misread Thai subtitles (a line that says `ดูหนัง` returns as `ดูหนึ่ง`). Use a contact sheet only to locate candidate time windows. Before a caption is reported as wrong, or passed, crop it at full resolution (`ffmpeg -ss T -i clip -frames:v 1` then crop the caption band) and read that crop alone.
- **Overlay text whose intended string is on disk (`gfx.json` headline, `subs.ass`, pills) is checked AGAINST that string, never transcribed blind — one line per crop.** Give the reader the candidate from the plan and ask MATCH/MISMATCH glyph-by-glyph on a `crop` of that single line's y band (y and size come from the gfx entry) at ~3×: free transcription of stylized Thai overlay invents a new syllable set on every call, and a full-band crop reads worse than a line crop. When candidate and reader disagree, the frame-change rule above applies — confirm on a second frame's crop before reporting a mismatch; never ship a mismatch verdict resting on one read.
- **A caption that lives only in the hook window (first ~2 s) survives mid/late sampling.** Frames at 4.5/8.0/9.3 s read clean while a Thai caption sat on screen from 0.3–2.0 s, so one of your samples must fall inside 0–2 s — and a text-ABSENCE verdict needs a band sweep, not full frames: crop the top and bottom ~260 px at 10–12 timestamps (`ffmpeg -ss T -i clip -frames:v 1 -vf crop=720:260:0:0`, and `crop=720:260:0:1020` for the bottom), tile each set `4x3`, and read every cell for presence. Two reads returning different strings for the same band mean the text is present but illegible (rule above): report the window, never the wording.
- **A wordmark or logo that is mid-animation at the sampled frame is not a truncated product name.** Logo reveals and wipes are partial by design. Re-sample about 1 s later before flagging it, and report it as a flag only when the settled frame is also wrong.
- **Consistent ABSENCE of a reference token across every independent read is a flag, not a pass.** The illegibility rules say quote candidates and let Fix judge — but when frames and zooms keep returning a slot-by-slot near-miss (`OMEGA … DAILY` with a different third word each read) and NEVER the reference's own word (`TRIPLE`) that the previously approved shot showed clearly, the pattern itself goes into `--frame flag:` with its frame times. Small print at 720p (~200 px label) makes each single read a guess; only the pattern — same slots agreeing, reference token never appearing on any frame — is reportable, never one read alone.
- The rest of the verdict rules (caption garble = defect, claim-word flips, stray props, cover-art fidelity, multi-scene seam continuity) stay in SKILL.md step 10.

## When vision reads fail mid-run
- Send vision a small JPEG (`scripts/vprep.py <img>` → `<img>.v.jpg`), one `vision_analyze` per tool batch. Before a message that ends the turn while the job is open: `clipjob.py wait <job> "<what is needed>"`.
- A provider-level `vision_analyze` failure (HTTP 400 naming an unsupported model, or repeated timeouts) is a transient work-stop, not a dead run — and never a serial-retry loop: probe once, then move on.
- Everything except the pixel gate runs without vision: render poll, download, `verify-clip.py`, log/state writes, and the next clip's submit. Do that work while the provider recovers, then slot the pending frame reads back in.
- If it never recovers in this run, state exactly which frame times went unread in the delivery — an unrun frame check is reported as NOT RUN, never as clean and never as an implied pass.
