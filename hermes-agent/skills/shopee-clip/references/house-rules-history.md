# House rules — the long versions (moved verbatim from house-rules.md on 2026-11-12)

The measurements, quotes and incidents behind the short rules in `house-rules.md`. The short rule wins where
they differ (the router, `clipjob.py` and the 2026-11-10 question flow replaced several of these).

- "ทำคลิปจากลิงก์นี้ <link>" / "สร้างคลิป Shopee สักคลิป" (+ ลิงก์สินค้า หรือแนบรูปสินค้า) / "gen ใหม่อีกคลิป" (regenerate with latest rules) / "ส่งคลิป" (resume a stuck download)
- **Once Fix has ordered a clip, drive the whole pipeline to delivery without per-step confirmation.** He decides when he orders; stopping to ask "จะให้ทำต่อไหม" at each stage just costs rounds. (Fix: "คราวหลังไม่ต้องถามผมเพื่อ confirm ทุก step ได้ไหม หลังผมสั่งครั้งแรกทำตั้งแต่ต้นจนจบได้เลยนะ")
- Deliver in one message at the end: clip + hashtags + 🛒 basket link.
- **First `unusual activity` card → manual mode for that product (Fix 2026-11-09):** no retry; see `references/flow-browser-env.md` → Manual mode.
- **When the run hits a blocker, tell Fix EARLY, not at the end (Fix: "คราวหลังระหว่างทางเจอปัญหาอะไรบอกผมด้วยผมจะได้เข้าใจว่าทำไมนาน" 2026-10-26).** A clip run cannot push a message mid-turn, so the rule that actually reaches him: cap silent retries at ONE — if the second attempt also fails (policy refusal, Failed card, login wall, picker dead), END THE TURN with a short status (what failed, what you tried, what you're about to do, whether credits moved) and continue next turn. Only a single cheap automated retry may run inside one turn, and its reason must appear in the final delivery. A three-refusal wall discovered only at delivery reads as a stalled bot to him.
- **Fix feels the END-TO-END wall clock, not the render — give him the split (2026-10-28: "เดี๋ยวนี้คลิป gen นานมากถึงจะแค่ 10 วิ").** Measured that run: Chrome up 15:45 → clip on disk 16:13 → delivered 16:31 ≈ **47 min total, render only ~10–13 min**; the rest was image prep (4 vision rounds), prompt + 3 chip-attach cycles, 8 frame-check vision reads and a 180 s Telegram upload timeout. So when he says generation is slow, quote that breakdown instead of agreeing flatly, and cut the avoidable half: do image prep WHILE the render runs (not before submitting), batch frame checks into as few vision calls as the tool allows, and once a delivery pipe has timed out once go straight to a background Bot API upload rather than burning another 180 s.
- **When Fix calls the clip off mid-run (`เลิกทำคลิปนี้` / `หยุด` / `พอแล้ว`), stop in place and close out in one pass.** Do NOT hunt for a cancel control inside Flow — there is no verified one, a render already queued runs server-side and may still finish on its own, and deleting its grid card only hides the asset; say that plainly instead of implying the render stopped. Write NO `/opt/data/clips/logs/clip-log.jsonl` row (that log is the record of what shipped) and record the abort in `/opt/data/clips/flow-state/<project-id>.json` instead: product, every `edit_id` you actually opened, the defect or reason that killed it, and `logged: false`, so the next run starts knowing what went wrong and what is already on disk to reuse. Close Chrome as the final act with CDP `Browser.close` (NOT pkill: a pkill marks the profile Crashed and the next launch restores every tab, which piled up 30 Flow tabs feeding Flow's reCAPTCHA; use `pkill -f '[c]hrome-fl[o]w'` only when CDP is dead), verify with `curl http://127.0.0.1:9222/json/version` returning nothing — never `pgrep`), then report spend honestly: a figure you never read stays "unreadable", it is never `0` and never the settings-panel number quoted as charged.
- **Put the money in the question text, and make an unanswered question cost nothing.** When a `clarify` choice changes how many credits get spent (use these extra images? re-gen which scene?), the cost belongs inside the question itself (e.g. "≈15 เครดิตต่อฉาก") because he answers from his phone without the surrounding delivery in front of him. An unanswered / timed-out / cancelled question resolves to the ZERO-spend option and is re-asked at most once, only that one question — a multi-question call routinely loses its second entry while he answers the first in free text instead of tapping, and a clip must never be generated on the strength of an answer he did not give. **A reply that carries images or prose but no chosen option is NOT an answer to that question — it is him handing over reference material: take it as input (crop and attach it), re-ask exactly once, and hold at zero spend if the re-ask also goes unanswered.**
- **Reference images that arrive with no order are input, not a job.** If Fix sends ad images with no instruction, ask ONCE via `clarify` with choices (run a new clip / use them in an existing clip / just keep them) and start nothing until he picks. Repeating the same question with new images, or starting a run on guessed intent, wastes his time. Ad-style images (overlay headline text, staged or AI-looking lifestyle shots) have had the same answer every time: storyboard-idea input only, never an attached reference. Apply that default, say so in one line, and do not re-ask.
- **Poll through to delivery inside the same turn — do not hand the wait back to Fix.** Ordering a clip includes the waiting: keep re-running the status snapshot until the file is downloaded, hashed and delivered. Stopping to report "still generating" reads as an unfinished job to him, and he checks the render on his phone while you sit idle (Fix: "ไม่เห็น poll ให้เองเลย"). If a run genuinely cannot finish, say exactly where it stopped — but never end on a passive wait you could have kept watching.
- **A queue of clips (several product links sent in one sitting): overlap the pipelines instead of running them end-to-end serially.** As soon as clip N passes verify + log + state, run clip N+1's whole submit (upload crop → attach character → type prompt → hit-test → Start generation) BEFORE composing clip N's delivery reply, so the next render is already burning while he reads; then end the turn with clip N's delivery and pick the queue up with a poll next turn. That is what answers a mid-queue "ยังทำต่ออยู่ไหม" — a clip that is visibly in flight, not a status line. Two orderings that only matter in queue mode: the hook LRU and the random character pick for clip N+1 must be computed AFTER clip N's log row is written (computing early repeats the hook and can repeat the same face across consecutive posts), and never let a queue make you skip the per-clip frame check — each clip is judged on its own pixels.
- **`/opt/data/clips/flow-state/<project-id>.json` — read in step 0, write back during the run.** Holds the project's known `/edit` ids (the ONLY way to know "is this the new clip?" — ids cannot be enumerated from any grid), the roster + last character used, the saved video defaults, and a note on what the stale agent instruction still says. `/opt/data/clips/logs/clip-log.jsonl` grows by one row in step 9 before delivery.
- **`scripts/verify-clip.py` replaces manual hash/probe/copy in step 8.** `python3 <skill_dir>/scripts/verify-clip.py [file.mp4]` (no arg = newest in either download dir) → sha256 uniqueness across BOTH dirs, ffprobe (720x1280 / h264 / aac / duration > 1 s), canonical copy to `/opt/data/home/Downloads/`, one JSON verdict, exit 0/1. Already proven: a fresh file returns `{"ok": true, ...}`. Its uniqueness check deliberately ignores the canonical copy of the same basename.
- After intake (step 1) and before Chrome/credits: build the board from `templates/storyboard.md` (4-6 shots of 4-6 s, mixed P/H/R shots, VO tied to each shot, graphics v2 plan, risky shots + fallback, credit estimate), send it as text, then `clarify` approve / edit / cancel. Unanswered = no generation.
- **Keep 4-6 shots, pace the submits (Fix 2026-11-09: *"นานหน่อยแต่คุณภาพดี"*, chosen over 2×10 s).** Start each Flow submit ≥5 min after the previous one, using review/post work to fill the gap, and quote the longer wall clock in the board. Reason: Flow's reCAPTCHA flagged the 5th back-to-back submit (`references/flow-browser-env.md` → unusual activity).
- A fresh Chrome session's first submit can return the `unusual activity` Failed card even with a plain User-Agent. It costs no credits: note it, wait at least 5 min, retry once, never loop.
- **ASK FIRST, before any pipeline work (Fix's standing instruction 2026-10-27: "หลังผมบอกให้ทำคลิป ถามผมกลับมาเลยว่าอยากให้ทำคลิปกี่วิ"):** the moment he orders a clip, ask BOTH questions **through the `clarify` tool in ONE call — two `questions` entries, each with `choices`, so Fix taps buttons instead of typing** (Fix 2026-10-31: *"ทำเป็นปุ่มให้ผมกดเลือกได้ไหมว่าจะทำคลิปแนวไหนแต่ default คือพรีเซ็นเตอร์เหมือนเดิม"*). Q1 อยากได้กี่วิ? → `["10 วิ (แนะนำ)", "20 วิ", "30 วิ", "40 วิ"]`; Q2 แนวคลิป? → `["presenter พรีเซ็นเตอร์พูดอธิบาย (แนะนำ)", "hands มือล้วน ไม่มีหน้าคน", "broll สินค้าล้วน หมุนช้า", "skit สถานการณ์ ปัญหา→สินค้า", "gameplay ตัดฟุตเตจเกม/ตัวอย่างเกม (0 เครดิต)"]` — presets in `templates/styles.md`, each says whether the character chip gets attached (only `gameplay` never renders in Flow at all: it is an ffmpeg assembly of real game footage, see that preset). Recommended (first) choice = the default in BOTH questions, so a skip/timeout/cancel needs no second round-trip: unanswered or `skipped` duration → 10 s, unanswered or `skipped` style → **`presenter`** (never treat a skip as "no style chosen, ask again"). These are the ONLY questions he wants on every order; they do not reopen per-step confirmation, which he banned — after they are answered, run end-to-end to delivery. Skip the duration question only when his order already names it; skip the style question only when he names a style (otherwise `presenter`, no second round-trip). Record the chosen preset as `"style"` in the clip-log row and `/opt/data/clips/flow-state/<project-id>.json` → `last_clip.style`.
- **Single-generation cap:** Omni 1.1 Flash offers 4/6/8/10 s, Veo 3.1 8 s — anything longer MUST be several scenes assembled. If an order names no duration → **10 s (default)**.
- **Profiles + credit math** (Omni Flash 720p = 7 cr/4 s → 15 cr/10 s, i.e. ~1.5/s; 360p cheaper): 10 s ≈ 15, 20 s ≈ 30, 30 s ≈ 45, 40 s ≈ 60. **40 s alone exceeds the 50-credits/day quota**, so for 30/40 s read the live `Generating will use N credits` line before submitting and tell Fix the figure (monthly Pro credits may cover it — only a number actually read on screen may be quoted).
  - **HARD GATE (Fix 2026-11-04: "คลิปที่ gen ออกมาเอาไปลง reel facebook ไม่ได้ทุกคลิปเลย… เพิ่มเติมข้อมูลให้เป็นเฉพาะคลิปที่มีการตัดต่อ scene ที่มากกว่า 1"): the xfade stitch MUST carry explicit output pixel/profile flags — `-pix_fmt yuv420p -profile:v high -level 4.0` (+ bt709 color tags).** With only `format=yuv420p` inside `-filter_complex` and no output flags, this ffmpeg build (Lavc61.19.101) still ships **`profile=High 4:4:4 Predictive` / `pix_fmt=yuv444p`**, which Facebook Reels' editor rejects with `ไม่สามารถเล่นวิดีโอได้` — single-scene Flow downloads are `High`/`yuv420p` and upload fine, so the failure tracks multi-scene clips exactly. **`verify-clip.py` now checks exactly this (profile / pix_fmt / level / faststart / audio format), so its exit 0 covers the gate — re-check by hand only if the script is unavailable. A `High 4:4:4 Predictive` reading = do not deliver, re-encode with the flags above (re-encode of the same stitch is lossless-ish at crf 18 and costs no credits).** **Re-encoding a BACKLOG: size the loop against the cell's own `timeout_s` (raise it explicitly — the 300 s default holds only ~12 encodes) — a timed-out `execute_code` returns no output and drops kernel state while the files already written survive, so verify a batch by scanning disk in a follow-up call, never by trusting the batch's own printout.**
  - **HARD RULE (Fix 2026-10-27): in any clip longer than 10 s, every scene that is NOT the last one must contain NO link/CTA wording at all** — no `ลิงก์อยู่ใต้คลิป`, no `ลิงก์อยู่ในคำอธิบาย`, no `พิกัดอยู่ใต้คลิป`, spoken OR on-screen. "Put the soft CTA only in the last one" was NOT enough: the HUAWEI WATCH GT 7 run still rendered `ลิงก์อยู่ในคำอธิบาย` at the end of scene 1 (visible at 9.65 s of the final cut) and Fix had to correct it afterwards. Write the prohibition INTO every non-final scene prompt as its own line — e.g. `ห้ามมีคำว่า ลิงก์ / ใต้คลิป / คำอธิบาย / พิกัด ใดๆ ใน scene นี้ ทั้งพูดและขึ้นบนจอ — CTA อยู่เฉพาะส่วนที่ 2 เท่านั้น` — and enforce it in the frame check: sample the last ~1 s of every non-final scene and RE-GEN the scene if a link caption is on screen. The agent's rewrite can reintroduce the CTA even when the prompt forbids it, so the pixel check is the gate, not the prompt alone.
- **Ad screenshots are not attachable references.** A product ad carries price, QR, watermark, claim text and sometimes a second product. Before using any image, vision-check for price/QR/watermark and for the product's full silhouette; crop only inside clean product area. A reference under ~1000 px on the long side, or with the product cut off by a banner, is not good enough to spend credits on. Ask for a clean photo once, with the reason, and wait — do not start Chrome on a weak reference. If Fix accepts a small-source crop instead (typical when the product is ~300 px inside a 950 px ad), follow `references/product-image-prep.md` → Small-source crops and name the quality risk in the delivery.
- Presenter + graphics preset: see `references/presenter-graphics.md` (subtitle style stays the house Itim style; graphics are added in post). **Graphics v2 (2026-11-07):** `scripts/presenter_fx.py` (hook card, punch-in zoom, product cutaways on raw scenes) → `post_presenter.py` → `scripts/graphics_layer.py --report report.json` (headlines ×4 styles, vector stickers, callouts, badges, endcard, sparkle cover, auto SFX, layout check incl. face `avoid`). **Fix picked v2 (2026-11-07) → it is the DEFAULT presenter build.** Product stills are cut-out stickers BESIDE the presenter (`presenter_fx` `"mode": "overlay"`), never full-screen cards that hide her.

## The other original bullets (short versions are in house-rules.md)
- Budget awareness: cost is **~1.5 credits per second at 720p** (measured 8 s = 12, 10 s = 15); higher resolution scales it further. PRO = 50/day ≈ **33 s of finished clip per day** — about 4 clips at 8 s, fewer if you make them longer. Read the Settings panel's "Generating will use N credits" line when it is visible. Check remaining credits before promising extras; tell Fix when the day's quota is used up. The narrow layout shows only the per-clip cost, not the remaining balance, so say "remaining unknown" instead of estimating from earlier clips.
- **Fix cannot inspect the Flow UI, so verify each step from the DOM and read-backs, never by asking him to look at the browser.** Report outcomes as text (credits, chip count, prompt length, filename in Uploads).
- **Answer repeated image sends once per batch.** While a reference is still missing, reply in one short line per new image (what it is, usable or not, what is still missing) and wait. Do not repeat the full status block each time.
- Ask only when genuinely blocked — credits already spent, a login wall, or a call only he can make — and state in that same message what you tried and where exactly it stopped, so he can steer instead of debugging blind. For a shot Flow keeps rejecting, use the manual hand-off in `references/flow-browser-env.md`.
- Never spend his credits to "try again" after a failed submit without saying so: the failed attempt did not cost credits, but a retry that lands twice does.
- **A short affirmative answering your own go/no-go question is the approval.** Replies such as "Ok" or "ได้" to a question like "resubmit scene 1, ≈15 credits?" are a yes; do not re-ask. A reply that only hands over an image is not an answer (see the rule above).
- **`templates/style-card.md` — paste its fixed block into every prompt (step 4).** The one-line-per-run "looks like one channel" layer: tone, caption font/placement, beat rhythm,  and the no-price reminder. **No shop watermark — Fix's standing call 2026-10-26:** never put a shop name/wordmark on screen, and never ask him for one. Product-specific lines stay in the beat list above it.
- **`templates/hooks.md` — pick the opener by category, least-recently-used from `/opt/data/clips/logs/clip-log.jsonl`.** Never reuse a `hook_id` for the same category within 5 consecutive rows; soft-CTA variants live there too.
- **`templates/hashtags.md` — pools per category** (`game`/`gadget`/`home`/`beauty`/`fashion`/`food`): 4 product + 3 vibe + 1 platform tag, then the same hard gate as before (≤150 chars incl. spaces, zero CJK/full-width codepoints, no price-flavoured tags). The LEGO Batman set came out 116 chars / no CJK — comfortably inside.
- **Female presenter, cute tone**, not too salesy / no hard-sell
- **Cute caption pills on screen while talking** (rounded, colorful, per beat, EN/คำยืม ≤2 คำ) — **เราใส่เองตอน post ด้วย `scripts/post_presenter.py`; Flow ต้อง render แบบไม่มีตัวหนังสือบนจอเลย** (ดู Presenter post-production ด้านล่าง) เพราะตัวหนังสือที่ Flow วาดเองเพี้ยน/แหกกฎ
- **Short but interesting** — ~10 s single scene is fine; Fix: "คลิปไม่ต้องยาวแต่น่าสนใจ"
- **No product size or dimension specs in the voiceover or on-screen** (Fix 2026-11-09). Listing sizes stay out even when printed on the reference photo.
- **Reference photos with no order are input:** vision-check for prices, promo text and claims, then ask once via `clarify` (product reference / storyboard idea only / hold). Ad-style lifestyle shots are not clean product references.
- **Modern Thai teen slang** (ปัง, เริ่ด, ของมันต้องมี, ดี๊ดี, คุ้มเว่อร์) — natural, not cringe
- Reason: two 10 s "hold / press / set down" takes read as filler; every shot must show the product working (vacuum bag: stuff blanket in -> zip -> press air out -> flat in wardrobe).
- This review gate is the confirmation he wants at that point; after approval run end to end (scene review gate still applies).
- Frame check adds one question per shot: did the planned action actually happen? If not, it is a defect.
- When the clip carries a lot of content (many feature/benefit lines, multi-claim voiceover, dense spec or use-case shots), do NOT add the soft CTA (`ลิงก์อยู่ใต้คลิปนะ` / `Link below!`) to the voiceover, the pills or the last scene. Let the content run to the end and leave the link to the caption/basket.
- Keep the CTA only for light clips where the last scene has room. Decide per clip and state the call in the delivery.
- **ห้ามพูดถึงราคา/ตัวเลขเงินเด็ดขาด** (no "2,390", no "ราคาดี๊ดี", no Baht figures, spoken OR on-screen caption). Fix: "ไม่อยากให้พูดถึงราคาเลย" (2026-09-27) — CTA แบบนุ่มนวลเท่านั้น (เช่น "ลิงก์อยู่ใต้คลิปนะ" / "ไปดูรายละเอียดกันได้เลย")
- **The rule covers INPUT images too:** never attach a product photo that carries price/promo text of its own (a crossed-out Baht figure, a "now only …" banner) — on-screen text inside an attached image can put a price on screen even when the voiceover has none. Attach the clean shots and say which ones you dropped.
- **Boundary — shipping is not a price:** "ส่งฟรี" / free delivery may appear on-screen only when Fix's own brief supplies it; every Baht figure, discount %, cashback amount and crossed-out price stays out, spoken or on-screen. Name any borderline caption in the delivery so he can decide on a regenerate (it spends his credits).
- **Boundary — dates are not a price:** a pre-order / release date ("พรีออเดอร์ 28 ม.ค. 2027") is product information, not money — it may go on-screen and into the voiceover. Do not strip dates out of caution; only money-shaped text is banned, and a date that dominates a beat still gets named in the delivery.
- **Efficacy and medical claims are never voiceover material unless a source Fix supplies backs them.** Ad graphics routinely print kill-rates ("99.9%"), endorsements (a hospital seal) and allergy/virus claims; none is verifiable from the image, so they stay out of the voiceover, the pills and the on-screen text. Crop such ad art down to the bottle before attaching (no claim text in frame), and say in the delivery which claims were left out.
- **Product dimensions are off-limits like prices** — no size/cm/inch numbers spoken or on screen unless Fix's brief supplies them for this clip.
- Structure: hook สั้น → จุดเด่น 1–2 ข้อ → CTA "ลิงก์ในคำอธิบาย" (นุ่มนวล) — **no price step**
- **Product size and spec numbers (dimensions, capacity, load ratings) stay out of the voiceover and on-screen text, the same as prices.** Numbers from a listing or an ad image are not clip material unless Fix names them. Unsourced performance claims (for example "good load capacity") stay out too.
- Vertical 9:16, Thai voiceover, sound ON
- Style reference: Shopee Video `sv.shopee.co.th/share-video/KUNZuOMsCgCKQAICAAAAAA==` (Sharp MODI, @mintrasumritmintt)
- **Shopee listing links usually hit a login wall.** Build the brief from the user's text and images; never take price, stock or spec from an unreadable listing.
- **No product size/dimension figures in the clip, spoken or on-screen.** Drop cm/mm/inch values even when a photo prints them, and name the dropped figure in the delivery.
- **A source image that shows a real child or other person is not a salvage source.** Crop the product only; if the product's bounding box touches or sits beside a person's body, the crop cannot be clean, so drop that image and ask for a product-only photo. Flow refuses person-bearing references, and a child's pixels must not reach the model even outside the frame.
- **Claims come from the product's own label or a source Fix confirms, never from ad copy.** Child-safety, efficacy, durability, load-bearing and award claims stay out of voiceover, pills and subs until Fix confirms each one. When the label and the ad disagree (e.g. age range), follow the label, keep the number out of the clip, and tell Fix.
- **Spec numbers that conflict across listing, ad and label** (dimensions, capacity, age) are omitted from the clip until Fix picks one; several sizes in the shop means no single size can be stated.
- **Credit approval is per product.** An approval given for one product does not cover the next one; re-confirm with the cost in the question text.
- **Once a clip order is clear, do not repeat the same question** across several image messages. Ask at most once, then act on the answer or hold.
