# lotto-picker

สุ่มเลข **2 ตัว / 3 ตัวแยกกัน** ไม่ซ้ำกับเลขที่ออกใน N งวดล่าสุด ผลรางวัลมาจาก API ของสำนักงานสลากกินแบ่งรัฐบาล (GLO)
หน้าเว็บใช้บนมือถือได้ ส่งเลขอัตโนมัติกับผลรางวัลเข้า Telegram และตรวจผลเลขที่บันทึกไว้ให้เอง

> แต่ละเลขมีโอกาสตรงกับเลขรางวัลหนึ่งเลขเท่ากันทุกงวด: 2 ตัว = 1 ใน 100, 3 ตัว = 1 ใน 1000 การตัดเลขที่เคยออกไม่ได้เพิ่มโอกาสถูก
> สถิติในหน้าเว็บจะเทียบจำนวนครั้งที่ถูกกับค่าที่การสุ่มธรรมดาคาดไว้ (`expected`)

## หน้าเว็บบนมือถือ

- ปุ่มเลือก **2 ตัว / 3 ตัว** อยู่เหนือเนื้อหา ใช้ได้ทุกหน้า; แยกฟอร์มที่ยังไม่บันทึก ผลสุ่ม ประวัติ สถิติ และค่าของเลขอัตโนมัติ โดยเปิดครั้งแรกที่ 3 ตัว
- เมนูล่าง 5 ส่วน: **สุ่มเลข / เลขที่บันทึก / สถิติ / ผลรางวัล / บัญชี**; จอใหญ่แสดงเมนูด้านบนและพื้นที่สุ่มสองคอลัมน์ (ปุ่ม 2/3 ตัวซ่อนในหน้าบัญชีเพราะไม่เกี่ยว)
- ปรับจำนวนงวดและจำนวนเลขด้วยปุ่ม +/− หรือค่าลัด; ตัวเลือกประเภทรางวัลและตัดโต๊ดอยู่ใน “ตัวเลือกเพิ่มเติม”
- เลขที่สุ่มแสดงเป็นตั๋วตัวใหญ่ คัดลอกได้ทั้งชุด และต้องกด **บันทึกไว้ตรวจผล** เพื่อเก็บเข้าประวัติ
- “เลขอัตโนมัติและการแจ้งเตือน” เปิด/ปิดทั้งการสร้างเลขอัตโนมัติและการส่งแจ้งเตือน; กด **ใช้ค่าชุดนี้กับเลขอัตโนมัติ** เพื่อบันทึกค่าการสุ่มปัจจุบัน
- ประวัติแยกรอผล / ถูกรางวัล / ตรวจแล้วไม่ถูก พร้อมประเภทรางวัลที่ถูก; ยืนยันก่อนลบชุดเลข
- “ตัวเลือกเพิ่มเติม” มี **สไตล์การสุ่ม** (สุ่มล้วน / ตามกระแส / สวนกระแส / ค้างนาน) และช่วงที่ใช้นับสถิติ; ใต้เลขที่สุ่มได้บอกว่าแต่ละเลขออกกี่ครั้งและค้างกี่งวด (ข้อมูล ไม่ใช่ %)
- ใต้ผลสุ่มมี **ใช้กับสลาก 6 หลัก**: รูปแบบ `xxx123` / `123xxx` / `xxxx12` พร้อมรางวัลที่รูปแบบนั้นลุ้นได้ คัดลอกได้ทั้งหมด
- หน้า **สถิติ**: ตารางความถี่ (2 ตัวเป็น heatmap 00–99), อันดับออกบ่อย/น้อย/ค้างนาน, ค้นเลข, ทดสอบย้อนหลัง และสรุปสถิติ
- หน้า **ผลรางวัล** มีช่องตรวจสลาก 6 หลักกับงวดที่เก็บไว้; หน้า **บัญชี** บันทึกเงินที่จ่าย/ได้ (ดูหัวข้อด้านล่าง)
- รองรับธีมมืดตามระบบ ปุ่มสัมผัสอย่างน้อย 44px และการนำทางด้วยคีย์บอร์ด

## ที่มาของผลรางวัล

- `POST https://www.glo.or.th/api/lottery/getLatestLottery` body `{}` คืนงวดล่าสุด
- `POST https://www.glo.or.th/api/lottery/getLotteryResult` body `{"date":"17","month":"01","year":"2026"}` คืนผลของวันนั้น ถ้าวันนั้นไม่มีงวดจะได้ `response: null`
- ไม่ต้องใช้คีย์ ตรวจสอบจาก NAS เมื่อ 2026-10-16
- `lotto.api.rayriffy.com` ที่สคริปต์ทั่วไปใช้ DNS ตายแล้ว

GLO ไม่มี endpoint ลิสต์งวด ระบบจึงเดินถอยหลังจากงวดล่าสุด ยิงเฉพาะวันใน `CANDIDATE_DAYS`
(1,2,3,15,16,17,28–31 เพราะงวดเคยเลื่อนเป็น 17 ม.ค. / 2 พ.ค. / 30 ธ.ค.) วันที่ได้ `null` จะเก็บไว้ในตาราง `nodraw`
และจะไม่ยิงซ้ำ ถ้าเลยไป 45 วันแล้วยังไม่เจองวดก็หยุด การ sync ปกติเติมให้ครบ N งวดที่ใช้ตัดเลข (สูงสุด 24)

**ประวัติลึกสำหรับสถิติ** (`service.backfill_history`, รันหลัง poll แรกตอน startup และทุกวัน 04:30): เก็บทุกงวดตั้งแต่
**1 ก.ย. 2558** (`lotto.HISTORY_START` งวดแรกที่มีเลขหน้า 3 ตัว 2 รางวัล — ก่อนหน้านั้น GLO ส่งเลขท้าย 3 ตัว 4 รางวัลและไม่มีเลขหน้า
ถ้ารวมกัน หมวด 3 ตัวจะมีความหมายไม่เหมือนกันตลอดช่วง) ไม่ใช้ walk ของ sync เพราะ 45 วันไม่พอกับช่วงงดออกรางวัลปี 2563:
รอบแรกยิงทุกวันใน `CANDIDATE_DAYS` ที่ยังไม่รู้จัก รอบสองยิง**ทุกวัน**ของเดือนที่จบแล้วแต่ยังเจอไม่ถึง 2 งวด (หางวดที่เลื่อนไปวันแปลก)
payload ที่ไม่ใช่ null แต่ไม่ครบเก็บใน kv `history_skipped` จะได้ไม่ยิงซ้ำ ความคืบหน้าอยู่ใน kv `history_status` (`GET /api/history`)
ครั้งแรก ~1,250 requests ราว 15 นาที (วัดจาก Mac 19/10/2569: ได้ ~265 งวด) แล้ว resume ได้เพราะทุกอย่างอยู่ใน DB ใช้ lock ของตัวเอง ไม่บล็อก sync/บันทึกเลข
**ห้ามรันก่อน poll แรก** — first-boot check ของ sync ดูจากตารางว่าง ถ้าประวัติเต็มก่อนจะประกาศงวดเก่าเป็นข่าว

**ระบบเก็บงวดเฉพาะเมื่อครบทุกรางวัล** (รางวัลที่ 1 = 1, รางวัลที่ 2 = 5, รางวัลที่ 3 = 10, รางวัลที่ 4 = 50, รางวัลที่ 5 = 100, ข้างเคียง = 2, หน้า 3 ตัว = 2, ท้าย 3 ตัว = 2, ท้าย 2 ตัว = 1)
GLO ปล่อยผลระหว่างการจับสด ถ้าเก็บงวดที่ยังไม่ครบ ข้อมูลครึ่งงวดจะค้างอยู่ถาวร
ส่วนวันที่ของงวดที่กำลังจับจะจดลง kv `latest_seen` ทันที

## การตัดเลข

**โหมด 2 ตัว**: สุ่มจาก `00–99` ตัดเฉพาะรางวัลเลขท้าย 2 ตัว (`last2`) ของ N งวดล่าสุด ปุ่ม “ตัดเลขกลับด้วย” เพิ่มการตัดเลขสลับหลัก เช่น `09 → 90`; เลขกลับไม่ใช่รางวัลที่ถูก ตรวจผลตรงตัวเท่านั้น

**โหมด 3 ตัว**: สุ่มจาก `000–999` ใช้กฎเดิม:

- **ทุกรางวัล** (ค่าเริ่มต้น): ใช้ 3 ตัวท้ายของรางวัลที่ 1–5 และรางวัลข้างเคียง รวมกับเลขหน้า 3 ตัวและเลขท้าย 3 ตัว
  ไม่นับเลขท้าย 2 ตัว และไม่นับ `n3` (สลาก N3 เป็นสลากอีกประเภท)
- **เฉพาะหน้า/ท้าย 3 ตัว**: ใช้แค่ 4 เลข
- **ตัดโต๊ด**: ตัดทุกการสลับหลักของเลขที่ออก ทำให้ pool แคบลงเร็วมาก

งวดหนึ่งมีเลข 3 ตัวไม่ซ้ำกันราว 155 เลข ถ้าย้อนหลัง 2 งวดจะเหลือเลขให้สุ่มประมาณ 714 เลข ถ้า 5 งวดจะเหลือประมาณ 429 เลข (วัดจากงวดจริง ส.ค.–ต.ค. 2569)

## สถิติ ทดสอบย้อนหลัง และสไตล์ (`app/analysis.py`)

ไม่มีอะไรในนี้ทำนายได้ ทุกตัวเลขมาพร้อม “ช่วงที่การสุ่มล้วนให้ได้” เพื่อให้เห็นเองว่าเลข “ร้อน” เป็นเรื่องปกติของการสุ่ม

- **หมวด**: 2 ตัว = `last2`; 3 ตัว = `targets` (3 ตัวท้ายรางวัลที่ 1 + หน้า 3 + ท้าย 3 = เป้าที่ใช้ตรวจผล), `first3`, `last3f`, `last3b`, `all` (3 ตัวท้ายรางวัลที่ 1–5 + หน้า/ท้าย 3) **ไม่นับข้างเคียง** เพราะเป็นรางวัลที่ 1 ±1 เสมอ
- **นับแบบมี/ไม่มีต่องวด** (เลขซ้ำในงวดเดียวนับ 1) expected คิดแบบเดียวกัน: `p = 1 − (1 − 1/U)^m` ต่องวด, จำนวนครั้ง ~ Binomial(n, p)
- **ช่วงปกติ** = quantile 2.5–97.5% ต่อเลข, **ออกบ่อยสุดปกติ** = median/95% ของค่าสูงสุดใน U เลข (`F(m)^U`), จำนวนเลขนอกช่วงที่คาด ≈ 5% ของ U — ไม่ใช้ chi-square เพราะ 2 ตัวมี λ ≈ 2.6 ต่ำกว่า 5
- **ค้าง** (`gap`) = จำนวนงวดตั้งแต่ออกครั้งล่าสุด (ไม่เคยออกในช่วง = จำนวนงวดทั้งช่วง)
- **สไตล์** (`style_candidates`): `hot` = นับมากสุด, `cold` = นับน้อยสุด, `overdue` = ค้างนานสุด เก็บ **หนึ่งในสี่** ของ pool ที่เหลือหลังตัดเลข (ไม่ต่ำกว่าจำนวนที่ต้องสุ่ม, ค่าเท่ากันตรงรอยตัดเอาหมด) แล้วสุ่มในกลุ่มนั้น — ใช้ฟังก์ชันเดียวกันทั้งตอนสุ่มจริงและตอนทดสอบย้อนหลัง
- **ทดสอบย้อนหลัง** (`backtest`): ทุกงวด t ใช้เฉพาะงวดก่อน t (ตัดเลข N งวด + นับสถิติ `window`) ค่าที่คาดว่าถูก = `k × |กลุ่ม ∩ เป้า| / |กลุ่ม|` คำนวณตรงไม่สุ่ม ผลจึงคงที่ เทียบกับ baseline สุ่มทั้งหมด ด้วย z-score เกณฑ์ **2.58** (variance ภายใต้ null ของค่าคาดหวังนั้นเอง `(k/|C|)²·|T|·q(1−q)`, `q=|C|/U` — ถ้าใช้ `k·p·(1−p)` ของจำนวนครั้งจริง z จะเล็กลง 2.5–8 เท่าจนไม่มีอะไรมีนัยสำคัญได้เลย) (เข้มกว่า 1.96 เพราะเทียบ 5 แบบพร้อมกัน) เริ่มนับเมื่อมีประวัติ ≥ 24 งวด
- ผลคำนวณ cache ในหน่วยความจำต่องวดล่าสุด (`service._cached`)

**สรุปสถิติ** (`app/insight.py`): `facts()` คำนวณทุกตัวเลขเอง → mimo เรียบเรียงเป็นภาษาไทย ≤6 บรรทัด แล้ว `check()` ตีกลับถ้า
มีตัวเลขที่ไม่อยู่ใน facts, มีคำแนวหวย (`BANNED` เช่น “เลขเด็ด”, “น่าจะออก”) หรือไม่มีบรรทัดปิดท้าย → ใช้ `template()` แทน
ไม่มี `MIMO_API_KEY` / ค้าง / ตอบเสีย = template เหมือนกัน รันใน thread (mimo ใช้เวลาเป็นนาที nginx timeout 300s) เก็บที่ kv `insight_2` / `insight_3`
หลังงวดใหม่ถูกประกาศ สรุปของโหมดที่เปิดแจ้งเตือนจะตามไปเป็นข้อความที่สอง (ไม่หน่วงข้อความผลรางวัล)

## บัญชีซื้อสลาก

ตาราง `ledger(draw_date, label, tickets json, cost, prize)` — ใส่เลขสลาก 6 หลัก (`123456 x2`) แล้วระบบตรวจรางวัลเองเมื่องวดนั้นอยู่ใน DB
(`lotto.ticket_prizes`: ใบเดียวถูกหลายรางวัลได้ รวมเงินทั้งหมด) ใส่ `prize` เองได้ (ทับการตรวจอัตโนมัติ) งวดที่ยังไม่มีผล = รอผล ไม่นับในยอดสุทธิ
วันที่ของรายการเป็นวันตามปฏิทิน (1/16) แต่ GLO เลื่อนงวดได้ (30 ธ.ค. แทน 1 ม.ค. ทุกปี) จึงจับคู่กับงวดที่เก็บไว้ใกล้สุดภายใน ±5 วัน (`service._resolve_draw`) และโชว์วันออกจริงในการ์ด
เงินรางวัลอ่านจาก `price` ที่ GLO ส่งมากับผลล่าสุด (kv `prize_amounts`, ค่าเริ่มต้น `lotto.PRIZE_AMOUNTS`) ใบละ 80 บาท (`TICKET_PRICE`)
**ได้คืนเฉลี่ยระยะยาว 60%** คำนวณจากตารางรางวัล (`lotto.expected_return`) ไม่ได้พิมพ์ค่าตายตัว

## การตรวจผล

เลขที่บันทึกไว้จะผูก `based_on` กับงวดล่าสุดที่ระบบเห็นตอนบันทึก (ก่อนบันทึกจะ sync ทุกครั้ง)
แล้วตรวจกับงวดแรกที่ใหม่กว่างวดนั้น เลขที่บันทึกหลังผลออกแล้วจึงไม่ถูกตรวจกับผลที่รู้อยู่แล้ว

โหมด 2 ตัวตรวจเฉพาะเลขท้าย 2 ตัว (`last2`), baseline `expected` คิดจากจำนวนเลขรางวัลไม่ซ้ำ / 100
โหมด 3 ตัวใช้ baseline เดิม / 1000 และประเภทที่ถูก:

- 3 ตัวท้ายรางวัลที่ 1
- เลขหน้า 3 ตัว
- เลขท้าย 3 ตัว
- โต๊ด 3 ตัวท้ายรางวัลที่ 1 (นับแยก ไม่รวมใน `exact_hits`)

| GET/POST | `/api/picks` | GET `?digits=2\|3` (default 3) แยกประวัติ; POST `{numbers, settings}` ตรวจจำนวนหลักตาม `settings.digits` |
| DELETE | `/api/picks/{id}` | |
| GET | `/api/draws` · `/api/stats` | draws `?limit=` (default 24); stats รับ `?digits=2\|3` (default 3) |
| GET | `/api/history` | สถานะ backfill + จำนวน/ช่วงงวดที่มี |
| GET | `/api/frequency` | `?digits&category&window` ตารางความถี่ + ช่วงปกติ |
| GET | `/api/backtest` | `?digits&picks&draws&scope&permute&window` |
| GET/POST | `/api/insight` | `?digits` GET สรุปที่เก็บไว้ (`running`, `stale`); POST เริ่มสรุปใหม่ (202) |
| GET/POST/PUT/DELETE | `/api/ledger` · `/api/ledger/{id}` | `{draw_date, label, tickets:[{number, qty}], cost, prize?}` GET คืน entries + summary |
| GET | `/api/check` | `?number=6หลัก&date=` ตรวจสลากกับงวดที่เก็บไว้ (ไม่ใส่ date = ล่าสุด) |
| POST | `/api/sync` | ดึงผลรางวัลทันที |
| GET | `/healthz` | healthcheck (ยิงตรงที่แอป ไม่ผ่าน nginx) |

ตั้งค่า 3 ตัวใช้ kv `settings`, 2 ตัวใช้ `settings_2`; เลขที่บันทึกเก็บ `digits` (และ `style`) ใน settings JSON — ไม่มี `style` = สุ่มล้วน
รายการเก่าที่ไม่มี `digits` ถือเป็น 3 ตัว ไม่ต้องเปลี่ยน schema หรือลบ/เขียนทับผลตรวจเดิม
โหมด 2 ตัว canonical scope คือ `last2`; โหมด 3 ตัวไม่รับ scope นี้
งวดเก่าที่ขาด `last2` จะซ่อมเฉพาะ field นี้จากผลทางการที่ครบและวันที่ตรงกัน ไม่ประกาศงวดเก่าใหม่ และไม่ตรวจเลข 2 ตัวเป็นแพ้ระหว่างที่รอข้อมูล

## Secrets / env

`secrets.manifest.yaml`:
- `LOTTO_TELEGRAM_BOT_TOKEN` / `LOTTO_TELEGRAM_CHAT_ID` → ใช้ bot ของ news-feed (`stacks.news_feed.telegram.*`) ส่งอย่างเดียว ไม่ได้อ่าน update จึงไม่ชนกับ news-feed
- literals `DATA_DIR=/data`, `PICK_TIME=20:00`
- `MIMO_API_KEY` → `shared.llm.mimo_api_key` (ร่วมกับ news-feed/shorts-factory) + literals `MIMO_BASE_URL`, `MIMO_MODEL`, `MIMO_REASONING_EFFORT=low` สำหรับสรุปสถิติ — `app/mimo.py` vendored จาก `shared/` (`make sync-shared`) ห้ามแก้สำเนา
- ไม่บังคับ: `LINE_CHANNEL_ACCESS_TOKEN` + `LINE_TO` (ถ้าว่างจะไม่ส่ง LINE) และ `PUBLIC_URL` (ใส่ลิงก์ท้ายข้อความ)

Basic auth ของ dashboard อยู่ที่ `stacks.lotto_picker.dashboard.basic_auth_user/basic_auth_password` → `nginx/.htpasswd` (gitignored):

```bash
export SOPS_AGE_KEY_FILE=~/.config/sops/age/keys.txt
U=$(sops -d --extract '["stacks"]["lotto_picker"]["dashboard"]["basic_auth_user"]' secrets/vault.sops.yaml)
P=$(sops -d --extract '["stacks"]["lotto_picker"]["dashboard"]["basic_auth_password"]' secrets/vault.sops.yaml)
printf '%s:%s\n' "$U" "$(openssl passwd -apr1 "$P")" > lotto-picker/nginx/.htpasswd
chmod 644 lotto-picker/nginx/.htpasswd
```
