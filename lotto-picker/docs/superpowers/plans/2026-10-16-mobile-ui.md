# Lotto Picker Mobile UI Implementation Plan

> **For agentic workers:** Use subagent-driven-development for isolated file ownership and final review.

**Goal:** Make Lotto Picker pleasant and easy to operate on a phone.

**Architecture:** Preserve existing APIs and vanilla static application. Separate interface into three navigable panels; maintain result and request state in app.js. Browser tests serve fixture API data from an isolated local HTTP server.

**Tech Stack:** HTML, CSS, vanilla JavaScript, pytest, optional Playwright for browser verification.

## Global Constraints

- Keep FastAPI APIs, lottery logic, schedules, settings defaults, database and authentication unchanged.
- Vanilla HTML/CSS/JavaScript only; no production dependencies or external font/CDN requests.
- Support 320px mobile through desktop, system dark mode, safe-area insets, keyboard focus and reduced motion.
- Touch controls at least 44px; input text at least 16px. No horizontal page overflow.
- Preserve leading zeros. Do not invent next draw dates or claim exclusion improves odds.
- UI verification uses fixture responses, with no GLO or Telegram traffic.
